## Existing tests changed on purpose
`supabase/tests/outreach.sql` lines 165 to 180 describe the exact stale-address situation SR-03 removes (an approved email keeps the old address after the contact changes). With the fix, the contact edit drops the email to draft, so three checks fail by design: "suppression list against the contact's current address", "against the address the mail is written to" and "contact person was deleted". They need a re-approve step after the contact change and, for the second check, to suppress the new address (the stored address now follows the contact). I did not edit that file (not mine). Exact change: after the `update public.brand_contacts set email = 'zz-out-k3-new...'` line add `update public.emails set status = 'approved' where id = '...0e4';`; replace the suppression of `zz-out-k3@example.test` by `zz-out-k3-new@example.test`; before the `delete from public.brand_contacts ... c3` check add the same re-approve line after the delete.
