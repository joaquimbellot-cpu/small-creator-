# Smallfold back office: project map (15 lines, read first). Branch audit-fixes, made from commit c3f03b6 (tag safety-before-audit).
1. WHAT: the private back office of Smallfold, which connects small YouTube creators with brands (creators, deals, stats, email outreach drafted with Claude). One Next.js app in admin/ also serves the public website (static pages written in src/, built by build.js into admin/public/). Live and PUBLIC on Netlify (free plan, server functions in us-east-2) with Supabase (free plan, Tokyo). Real data exists only in production; the local test stack has fake data.
2. STACK AND SIZE: Next.js 16 App Router, React 19, TypeScript 7, @supabase/ssr + supabase-js 2.119, zod 4, @anthropic-ai/sdk, nodemailer, papaparse, vitest. No ESLint and no lint script. About 6.9k lines of TS/TSX, 11 SQL migrations (2.8k lines, admin/supabase/migrations), 2k lines of e2e scripts (*.cjs), 26 pages, 13 API routes, 15 server-action files.
3. REQUEST GATE: admin/proxy.ts runs on every path except /_next/static, /assets, robots.txt and favicon. Website pages get security headers only. The public paths /login, /forgot-password, /reset-password, /auth/*, /unsubscribe/*, /api/unsubscribe/* and /api/public/* pass without a session. Everything else needs a session (redirect to /login, or 401 JSON for /api). It sets a CSP with a per-request nonce. Session check: lib/supabase/proxy.ts, getClaims().
4. STAFF CHECK: lib/auth/staff.ts load() (React cache): getClaims, then the profiles row (row-level security lets only active staff read it), giving Staff {id, role}. requireStaff()/requireOwner() must run inside EVERY page and server action ('use server' files: app/(auth)/*/actions.ts, app/(company)/*/actions.ts, app/unsubscribe/[token]/actions.ts, lib/auth/actions.ts).
5. API WRAPPER: lib/api/handler.ts apiHandler({role, body, query}) does a same-origin check for writes (Origin / Sec-Fetch-Site), getCurrentStaff, the owner check, zod parsing and JSON errors. 10 of the 13 routes use it. NOT wrapped: api/public/apply and api/public/contact (no login; Origin check, honeypot, per-visitor limit on a keyed IP hash, then a service-role RPC, see lib/forms/public.ts) and api/unsubscribe/[token] (signed token, lib/email/token.ts).
6. ROLES: owner (everything: delete, CSV export, Settings, staff, audit log, Claude page) and worker (view and edit creators, deals and templates, draft and send emails, CSV import, Inbox). Checked in the app and again by row-level security (public.is_staff()/is_owner()). With a verified 2FA factor, only an aal2 session counts as staff (migration 20261121000800_security_hardening.sql).
7. LOGIN: app/(auth)/login/actions.ts. login_allowed(email, ip) refuses after 5 failed tries in 15 minutes PER EMAIL and also PER IP. Then record_login_attempt, Supabase signInWithPassword, the optional TOTP step at /login/2fa, and the audit line auth.login. Client IP (lib/auth/ip.ts): x-vercel-forwarded-for on Vercel, else x-nf-client-connection-ip, else x-real-ip, else one shared bucket 'local'. Supabase sign-up is off; staff are invited from Settings, Users.
8. PAGES: (company): overview, creators (+ /creators/import and a pop-up dialog), deals, emails (compose, review, [id], templates), inbox (+[id]), claude, settings (sending, users, security, audit). (auth): login (+2fa), forgot-password, reset-password. Public: unsubscribe/[token], auth/hash, auth/confirm (links in Supabase emails).
9. DATABASE: 15 tables (creators, brands, deals, emails, email_templates, suppression_list, settings (one row), profiles, audit_log, login_attempts, contact_messages, form_rate_limits, assistant_threads, assistant_messages, assistant_proposals), the view creator_summaries, 27 policies, about 30 functions (many SECURITY DEFINER: reserve_send, mark_sent, mark_failed, stats_overview, recent_activity, bootstrap_owner, log_audit, login_allowed). audit_log is append-only, filled by audit_row() triggers and by log_audit() from lib/audit.ts.
10. EMAIL FLOW: compose -> drafts (lib/drafting: Claude, or mock mode when there is no key or DRAFT_MODE=mock) -> Review -> Approve -> a person clicks Send -> POST /api/emails/[id]/send (lib/email/send.ts) -> reserve_send (actor must be active staff; email approved; not suppressed; creator not do_not_contact; daily limit, 30 by default; gap between sends, 5 s; test mode sends to the test address with [TEST]; real sends need a postal address) -> nodemailer SMTP -> mark_sent or mark_failed. Footer with a signed unsubscribe link plus List-Unsubscribe headers.
11. CLAUDE PAGE (owner only, lib/assistant): loop.ts (at most 12 tool steps per message, 100 messages a day), tools.ts (reads named columns only, never email, phone or notes; database text wrapped as untrusted by untrusted.ts; may save drafts; every other change becomes a proposal the owner approves by a click). No tool sends, deletes or exports. Drafting: lib/drafting (facts.ts, prompt.ts, validate.ts).
12. LOCAL STACK (fake data, already running): Postgres 127.0.0.1:54322 (psql -h 127.0.0.1 -p 54322 -U postgres), gateway :54321 (/auth/v1, /rest/v1), mail catcher http://localhost:8025 (SMTP 1025), fake Claude :4010, and the built app at http://localhost:3000 started with EMAIL_FROM=smallfold-test@example.test. Logins and the expected numbers: admin/supabase/seed/EXPECTED.md (owner@example.test, worker@example.test). admin/.env.local holds fake test keys.
13. TESTS: admin/tests/run-all.sh runs, in order, the DB tests (supabase/tests/run.sh: SQL checks in one rolled-back transaction, then HTTP checks through the gateway), vitest, QA e2e, the creators, deals, email, website, forms and assistant e2e, and auth e2e last (it trips the login limit). Playwright is installed: require('playwright') works anywhere, or use NODE_PATH=/opt/node-tools/node_modules. Run a single e2e with BASE_URL=http://localhost:3000 node <file>.
14. STATE IN PRODUCTION (not reachable from here): test mode OFF, sender postal address empty (so real sends are refused), no SMTP_PASS (Gmail not finished), no ANTHROPIC_API_KEY, 17 real creators imported. The GitHub repository is PUBLIC. Docs: docs/handoff.md (status and rules), docs/launch-plan.md, docs/backend-plan.md, admin/README.md (setup guide), admin/.env.example.
15. OWNER'S RULES the code must keep: personal data (emails, phone numbers) never readable from the public site; every API route checks the session, the role and its input; login attempts are rate-limited; the audit log records who viewed, edited, exported or sent what; no secrets in code or git; no home-made password system; Claude never invents facts and never receives a creator's email, phone or notes; nothing is sent without a click on Send, and only from the server; every email has the sender's identity and an opt-out line; opt-outs and "do not contact" block every send.
