# 04 Functional QA

## 1. Scope and method

I used the running app at http://localhost:3000 in Chromium (Playwright), as owner and as worker, on the fake local data. I did about 20 scripts: login, logout and wrong passwords (made-up emails only, own `x-real-ip` 10.77.4.x), logged-out access to every back-office address and API, role checks (pages, buttons and direct API calls), the creators list (all 8 sorts, status filter, search, paging, empty and out-of-range), the creator pop-up (view against SQL, add, edit, delete, bad input), CSV import (14 files) and export, deals (add, stage, filter, delete, commission), the Overview (every number and the chart against raw SQL taken at the same moment), the Inbox (real website form), templates, and one visit to every other page plus a link crawl (80 links as owner, 72 as worker). I also ran `admin/lib/creators/e2e.cjs` (62 passed), `admin/lib/deals/e2e.cjs` (all passed) and `admin/tests/website.e2e.cjs` (all passed). I did not run `admin/tests/qa.e2e.cjs`, because it sends a wrong password for `owner@example.test` and could trip the shared login limit. Everything I created was named "ZZ AUDIT" and deleted. No code or configuration was changed.

## 2. Done well

- Logged out, every back-office page redirects to `/login?next=...` and every API answers 401 JSON. After logout the cookies are gone, the back button only shows `/login`, and a copy of the old session cookie is refused (401).
- Login: wrong password and unknown email give the same message. After 5 failures the 6th try says "Too many attempts. Try again in 15 minutes." The `next=` parameter ignored `//evil.com`, `https://evil.com` and `/\evil.com`.
- Role split is correct in both the screen and the server. The worker sees no Delete, Export CSV, Settings, Claude or Audit link, and direct calls fail: `GET /api/creators/export` and `DELETE /api/creators/:id` return 403, the Claude APIs return 403, and writes without an Origin header return 403. Owner-only pages redirect the worker to `/overview`. All of these work for the owner.
- All 8 sort orders matched SQL on the first 25 rows. Status filters matched the database counts (18, 12, 8, 10, 10, 2). Search for "wren" returned 3, as SQL does. Search text such as `%`, `_`, `"`, `a,b` and `<script>` does not break anything.
- The pop-up details matched the database for 6 creators (hidden subscribers, no phone, deals, earned amount). Duplicate emails are refused, even with different letter case. Delete asks first, and Cancel really cancels.
- Messages for bad input are clear (name, email, phone, channel link, subscribers: negative, text, decimal and over 100,000,000). An HTML tag in a name or note does not run.
- CSV import: wrong header, empty file, header only, bad quoting, a file over 1 MB, 2001 rows, and a PNG saved as .csv are all refused with a clear message. Duplicates (same file, existing email, existing channel) and bad rows are labelled by line number. A BOM, semicolons and a quoted multi-line cell work. The server re-checks the file.
- CSV export: owner only, the audit line `creators.exported` is written, and cells starting with `= + - @` get a leading quote.
- Overview: for both roles every card, the deals-by-stage numbers, the 12 weekly bars and the chart table equal my own SQL (28 sent, 5 in 7 days, 16 in 30 days, 12 replies, 42.9%, 8 active deals, $219.00 commission, weeks 26 sent and 11 replies; the 12th reply is older than 12 weeks).
- Deals: commission shown in the list equals the database for every amount tried. Typing a brand in lower case reuses the existing brand. A deal delete asks first and the owner-only rule holds. A creator with deals is refused clearly (409 message).
- Inbox: a message from the public brand form appears, the worker can mark it handled, and the owner can delete it. Templates: unknown placeholders are refused, the worker can create and edit, and only the owner sees Delete.
- No 500 errors and no real console errors on any page in either role (the only console messages were font CORS noise caused by my test header, and expected 404s on invalid ids). No broken links.

## 4. Not checked or limits

- Email sending, drafting and the Claude page were left to the other agent as instructed. I only opened the Emails, Compose, Review and Email detail pages, and sent no email.
- Not run: `admin/tests/qa.e2e.cjs` (it tries a wrong password for the owner address, which could lock the shared login). Not saved: Settings → Sending and Users invite (changing sending settings or sending an invite could affect others); I only checked page content. The form checks I tried were stopped by the browser's own validation, so the server-side limits there are unverified.
- Not committed: a 2000-row import (only previewed, which took about 1 second), to avoid creating 2000 rows. Subscriber refresh is off (no YouTube key), so it was not tested. Two-step login was not tested (it would change the owner's account).
- Date counts such as "emails sent 7 days" were checked with raw SQL, but the figures can change if other agents add data. The creator count on the Overview (73 at the end) includes five "ZZ AUDIT Creator" rows from other agents.
- Leftovers: none of my rows remain. My failed-login test on made-up addresses left rows in `login_attempts` (email `zz-audit-lock@example.test`, IP bucket 10.77.4.201), which I cannot delete (read-only database and no UI).

Score: 8/10. Core flows (roles, lists, edits, CSV, deals, Overview numbers) are correct and safe, with no 500s; the gaps are an export that cannot be re-imported, misleading out-of-range pages, no way to edit a deal amount, and a few small input-checking and mobile problems.
