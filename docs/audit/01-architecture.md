# 01 Architecture and code quality (agent 1)

## 1. Scope and method

- Read all of `admin/app`, `admin/lib`, `admin/components`, `admin/proxy.ts` for structure, layering, error handling and types (about 8.9k lines including the e2e scripts). Checked every server action, page and API route for its auth call and Supabase client.
- Ran: `npx tsc --noEmit` (clean, exit 0), `npx vitest run` (8 files, 63 tests, all pass), `npm audit` and `npm audit --omit=dev` (0 vulnerabilities), `npm outdated` (nothing outdated), `npx oxlint` (11 warnings, none serious), `npx knip` (15 unused files, 22 unused exports, 5 unused types).
- Ran `next build` with `NEXT_DIST_DIR=.next-a1`. A distDir in the scratch folder is rejected by Next 16 (`InvalidDistDirError`: it must be inside `admin/`), so I used the git-ignored folder `admin/.next-a1`, then deleted it. The build passed with 0 warnings (42 routes, all dynamic). It changed `admin/tsconfig.json`, which I restored with `git checkout -- admin/tsconfig.json`. The build also re-ran `npm run tokens` and `npm run site`, which rewrite the git-ignored `app/tokens.css` and `public/` with identical content.
- No login tests, no email, no network calls other than the npm registry. `git status --short` at the end: only this report is new.

## 2. Done well

- Layering is clean. `import 'server-only'` is on all 23 modules that hold secrets or the service-role client. No `'use client'` file (26 of them) imports anything but `components/ui`, constants, formatters, types and `lib/supabase/browser.ts` (which reads only the two `NEXT_PUBLIC_` variables). No secret is reachable from the browser bundle.
- `requireStaff()` runs in the `(company)` layout and again in every page. Every owner-only page, server action and API route calls `requireOwner()` or `role: 'owner'`. All 13 (company) server-action files call `requireStaff` or `requireOwner` in each exported action. 10 of 13 routes use `apiHandler`; the 3 others are the documented public ones and each is consistent with the map.
- The service-role client has 8 call sites, all in the places the comment in `lib/supabase/admin.ts` allows (login rate limit, invites, unsubscribe, send guard, public forms). Everything else uses the user client, so row-level security applies.
- Input validation: zod at every API boundary and every form action; the CSV import re-checks the file on the server; search text is quoted and escaped (`lib/creators/filters.ts:41`).
- Error text shown to users is generic ("Something went wrong."); logs hold codes and short messages, not bodies, addresses or keys. Comments explain why ("Log the type only; the message could contain request details").
- Types: `tsc --noEmit` is clean with `strict: true`; only one `any` in the whole app. Dependencies are current, 0 advisories, lockfile committed and consistent.
- Small, well-commented modules; one place for each concern (`lib/api/handler.ts`, `lib/auth/staff.ts`, `lib/audit.ts`).

## 4. Not checked or limits

- I did not test behavior in the browser, logins, email sending or the assistant: other agents cover those. Findings marked "unverified" (ARC-04 recovery of a stuck `sending` row, ARC-06 effect on Netlify) need a run against the real hosting limits.
- Row-level security, SQL and the schema are for the database agent; authentication strength, headers and the CSP are for the security agent. I only noted code-structure facts about them.
- The static website builder (`build.js`, `src/`) was not reviewed beyond the fact that the `npm run site` step succeeds and writes to `admin/public/`.
- oxlint was run with its default rules only; no type-aware lint was run. `npm audit` needs the registry, so a new advisory could appear after today (2026-11-23).
- Test coverage was judged by reading which modules the 8 vitest files import, not by a coverage tool.

Score: 8/10. The layering, server-only discipline, validation and dependency health are better than most projects of this size; the open points are silent error handling in a few actions and pages, the missing generated database types, no CI, and thin unit tests on the security-relevant helpers.
