# Security audit (agent 2)

## 1. Scope and method

- Read the code of the request gate (`admin/proxy.ts`), `lib/auth/*`, `lib/api/handler.ts`, the login, reset and invite flows, every `page.tsx`, `route.ts` and `'use server'` file, the CSV code, the email send path, the public forms, the unsubscribe code, `lib/assistant/*`, and the SQL policies, grants, triggers and functions (read from the live local Postgres with psql).
- Searched the whole git history (`git log -p --all`, 89 commits, 11 MB) and the working tree for keys, JWTs, `sbp_`, `sk-ant-`, private keys, app passwords and non-test email addresses. Also searched the built browser bundle for the values of the server-side secrets.
- Tested against http://localhost:3000 and the gateway http://localhost:54321 as anonymous, worker and owner (Playwright, curl, psql). Every wrong-password test used made-up addresses and my own `x-real-ip` (10.77.2.x). I created one throwaway user with a TOTP factor through the local GoTrue admin API to test deactivation and 2FA, and no real email or Claude call was made.
- Cleaned up afterwards: all `ZZ AUDIT` creators, contact messages, the test user, my login-attempt rows, and the two Claude conversations titled "hi" that my owner test made. `git status --short` is clean. The immutable audit log still holds lines my tests wrote (for example a forged `creators.exported`, id 399).

## 2. Done well

- **Secrets:** nothing found in the working tree or in the 89 commits (no JWT, `sbp_`, `sk-ant-`, private key, app password or service key; `.env.example` has empty values). `admin/.env.local` and `admin/dev/.data/secrets.json` are git-ignored (`git check-ignore` confirms). The only business address in history is the public contact address of Smallfold. Only the anon key is in the browser bundle (checked against the values of the four server secrets).
- **Public key is useless on its own:** with the anon key and no login, all 16 tables and views return 401 "permission denied", and no function in `public` is executable by `anon` (psql grants check). Sign-up is off, and the GoTrue admin endpoints return 403.
- **Role checks hold everywhere I tested** (table below). Anonymous gets a redirect or 401 on every page and API. A worker gets 403 on CSV export, delete, all `/api/assistant/*`, and is redirected away from `/claude` and every `/settings/*` page. Row-level security independently blocks the worker: audit log and Claude tables return nothing, `reserve_send` and `login_allowed` are refused, and a role change to owner updates 0 rows.
- **2FA is enforced by the database, not only the app:** with a verified TOTP factor, an aal1 token reads 0 rows of `creators` and `profiles`, and `log_audit` answers "forbidden". A deactivated user's old token reads 0 rows at once, and the app's remove action also bans the account.
- **Injection:** the PostgREST search filter quotes and escapes user text. Eleven hostile search strings (quotes, commas, brackets, `%`, `\`, `*`, CR/LF, SQL) changed nothing. CRLF in a subject or sender name is neutralised by nodemailer (tested). CSV import refused an unterminated quote, 1.1 MB, 2,001 rows, empty or binary files, and a 6 MB upload. CSV export prefixes `=`, `+`, `-`, `@`, tab and CR cells with a quote.
- **XSS:** no `dangerouslySetInnerHTML`, `innerHTML` or `eval` anywhere in the app or the website source. A `<img onerror>` payload sent through the contact form shows escaped in the Inbox list and the message page. Only `https://` channel links become clickable (a stored `javascript:` link is shown as text). The CSP uses a per-request nonce with `strict-dynamic`, `object-src 'none'`, `frame-ancestors 'none'`, `form-action 'self'`, and no `unsafe-eval` in production.
- **CSRF and redirects:** server actions use Next's own Origin check. `apiHandler` refused `Origin: evil`, `Origin: null`, `Sec-Fetch-Site: cross-site` and `same-site` (403). The public forms refuse a missing or foreign Origin. `?next=` goes through `safeNext` (rejects `//`, `\`, tab and encoded variants). The reset and invite emails build their link from `NEXT_PUBLIC_SITE_URL`, not from the Host header.
- **Rate limits work as designed through the app:** 5 failures lock an email from any IP, and 5 failures lock an IP across emails; the public forms stopped at the 6th post in an hour (429). Claude is owner-only with a daily limit and 12 tool steps per message.
- **Unsubscribe:** HMAC-signed token (constant-time compare), opening the page does not unsubscribe, a bad token gets one neutral wording, and no email, phone or note is shown anywhere public.
- **Claude never receives email, phone or notes:** tools name their columns, database text is wrapped as untrusted with angle brackets stripped, and every change is a proposal the owner approves with a click (details built from the stored payload).
- **Audit log is append-only:** `UPDATE` and `DELETE` raise "audit_log is append-only" even for the `postgres` role; `authenticated` has only SELECT and `service_role` only INSERT and SELECT. `log_audit` accepts only a fixed list of action names and a size limit.
- **Email gate in the database:** a worker cannot set `sent`, cannot edit a sent mail, and an edit to an approved mail drops it back to draft (`emails_guard`).

## 4. Not checked or limits

- **Production** (Supabase, Netlify, Gmail) was not touched, per the brief. Supabase's own auth rate limits, whether the owner has 2FA on, Netlify's real header behaviour (`x-nf-client-connection-ip`, `netlify.toml` headers) and the actual email send limits are `unverified`.
- The local gateway proxies to a real GoTrue, but its rate-limit settings are not Supabase's cloud settings, so SEC-01 shows the app does not limit, not what Supabase would allow.
- Server actions were verified by reading the code and by RLS tests, not by replaying forged action IDs.
- I did not send email, so the final recipient list in SEC-02 was shown with nodemailer's parser (`jsonTransport`), not through the mail catcher.
- I did not test the TOTP enrolment screens in the browser, the Claude model with prompt-injection text (the fake Claude on :4010 would not behave like the real one), or the YouTube refresh (no key set).
- Dependency versions and `npm audit` (architecture agent) and schema design (database agent) were left to them. SEC-02, SEC-06 and SEC-13 are included only because they let data or opt-outs leak.
- Legal remark (observation, not advice): the history holds one public Smallfold contact address and only fake creator data; the website mock-ups use made-up names.

Score: 7/10 for solid role checks, a locked-down public key, strong CSP and a real append-only log, held back by the bypassable login limit, optional 2FA for the owner only, and audit and export controls that a worker can step around.
