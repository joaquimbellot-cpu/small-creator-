# Security re-audit (verification agent V2), branch audit-fixes

## 1. Scope and method

- Re-read the whole change set `git diff safety-before-audit..audit-fixes` for security: `proxy.ts`, `lib/api/handler.ts`, `lib/auth/*`, cookie code, login, reset, 2FA, unsubscribe, health, audit and Claude code, every `'use server'` file (first line of each checked), and the three migrations `20261123000100/200/300`.
- Secrets: working tree (`git ls-files`) and all 109 commits searched for JWTs, `sbp_`, `sk-ant-`, private keys and app passwords. Clean. `npm audit --omit=dev`: 0 vulnerabilities. `vitest`: 122 pass.
- Database (psql read-only plus the gateway with the anon key, a worker token and an owner token): grants, RLS flags, 36 policies, ACL of every function, `SECURITY DEFINER` functions without `search_path` (none), executable-by-anon list (empty), and live probes of every new guard.
- App (Playwright and curl on :3000): role matrix on 19 pages and 11 API routes for anonymous, worker and owner; CSRF and content-type; cookie flags, logout and cookie replay; `?next=`; login limit (pair, IP and cross-IP rules); reset limit; public forms; one-click unsubscribe; reset-link flow; headers; a temporary worker with a verified TOTP factor (aal1 versus aal2).
- Wrong-password tests used only made-up addresses (zz-v2-*) and my own `x-real-ip` (10.66.2.x). No real mail, no real Claude. Test creators, contact messages, suppression rows, the temporary user and email drafts were deleted. `git status --short` shows only this report.

## 2. Done well

- **Nothing leaks:** no secret anywhere in the tree or history; anon key reads nothing (all tables 401, no RPC executable by anon or PUBLIC); new tables (`reset_requests`) have RLS and no client grant; every `SECURITY DEFINER` function has a fixed `search_path`; the default-privilege fix works (no function in `public` is executable by PUBLIC or anon).
- **Role checks held on every page, route and action:** anonymous gets 307 or 401 everywhere; worker gets 403 on delete, export and all Claude routes and is redirected from owner pages (`/overview?notice=owner-only`); `/settings` sends a worker to `/settings/security`; owner gets 200. All 24 server actions call `requireStaff()` or `requireOwner()` before anything else (the public ones are public by design).
- **CSRF:** a body route without `application/json` gets 415 (text/plain, form-urlencoded, none); evil, `null` and cross-site Origin or Sec-Fetch-Site get 403 on delete, send, import and approve; public forms refuse a missing or foreign Origin.
- **Session cookie:** HttpOnly, Secure, SameSite Lax, 30 days. Logout clears it, and replaying the old cookie gives 401 or 307, so the cookie change did not break logout.
- **Login limit works as designed:** 5 failures lock the (email, IP) pair on the 6th; the same email from another IP is still allowed; the same IP with another email is blocked; the email-wide cap trips on the 21st distinct IP. A failed Auth outage is not counted.
- **Reset limit works:** 3 per hour per address and per IP, always the same neutral answer.
- **2FA enforced in the database for workers too:** worker with a verified factor at aal1 reads 0 creators and 0 profiles and gets 403 from `log_audit`; at aal2 reads data again.
- **Do-not-contact guard holds against a worker:** setting works and adds a `manual` suppression row; lifting, lifting after changing the email, and deleting the suppression row all fail; the owner can lift; a worker cannot delete creators.
- **Email gate:** worker cannot set `sent` or `sending` (400); a list in `to_email` is refused by the new check; `reserve_send` checks suppression on both the row address and the creator address.
- **Unsubscribe endpoint:** POST only (GET 405), HMAC token with constant-time compare, bad or forged tokens 404, a valid POST opts out, marks the creator do not contact and writes an audit line.
- **Audit log:** UPDATE and DELETE denied for authenticated; email lines no longer carry `to_email`; creator edits of email, phone and notes store only `changed`; viewing the edit page now writes `creator.viewed` (count 21 to 23 after one edit page and one API view); `assistant.thread_deleted` is written by the owner delete.
- **Public forms:** 5 per hour per IP (6th gets 429), oversize and bad input 400, a `javascript:` channel goes into the notes, not the link field, and `<img onerror>` text is stored as text; no `dangerouslySetInnerHTML` or `innerHTML` anywhere.
- **Headers:** CSP with nonce and `strict-dynamic`, no `unsafe-eval` in production, `frame-ancestors 'none'`, HSTS, nosniff, Permissions-Policy on both back office and website; fonts are now self-hosted so the back-office CSP no longer lists Google.

## 4. Not checked or limits

- Production Supabase and Netlify were not touched: Supabase's own Auth limits (SEC-01), whether the Netlify runtime sets `NETLIFY`, `SITE_ID` or `DEPLOY_ID`, the real `x-nf-client-connection-ip` behaviour, and the `netlify.toml` header rules are `unverified`.
- The global cap of 200 form posts per hour was read in `form_rate_ok` and covered by `fixes.sql`, not flooded live (it would fill the shared Inbox).
- `release_stale_sending` and the creator delete with a sent email were not re-run live; I only read them and checked the ACLs and the constraint type.
- The login 20-per-email rule and the 5-per-IP rule were tested with my own x-real-ip values; they cannot show how real Netlify IPs behave.
- Prompt injection against the real Claude was not tested (fake Claude on :4010). Tool code was read: no email, phone or notes are returned to the model, and a new address in `propose_add_creator` must be one the owner typed.
- Side effects I could not undo: my append-only audit lines (about 10, including 3 fake worker lines), `login_attempts` rows for zz-v2 addresses and `reset_requests` rows for 10.66.2.x (they age out).

Score: 8/10: every Phase 1 fix I tested holds, with no new hole above Medium and no regression in logout, cookies or role checks; what remains is the Supabase-side login limit and the worker read of all creator data (both owner decisions), plus the lock-out and audit-line gaps above.
