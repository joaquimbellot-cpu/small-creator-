# 05 Email and Claude integration audit (agent 5)

## 1. Scope and method

- Read all of `admin/lib/email`, `lib/drafting`, `lib/assistant`, `app/api/emails`, `app/api/assistant`, `app/(company)/emails`, `app/unsubscribe`, `app/api/unsubscribe`, and the SQL `reserve_send`, `mark_sent`, `mark_failed`, `emails_guard`, `opt_out`, `suppression_*`, `audit_row` (migrations 0300, 0400, 0800, 0900, 1000).
- Ran against the local stack only (`SMTP_HOST=localhost` checked first; mail only reached the catcher at :8025). Tools: curl, Playwright (own `x-real-ip` 10.77.5.x), psql read-only, REST calls with the staff logins, and `npx tsx` for the draft validator.
- Started two extra copies of the built app (ports 3105 and 3106) with their own runtime variables: Claude down and SMTP down on one, a scratch fake Claude (my own, port 4111, with crafted answers) on the other. Both copies and the scratch fake are stopped. Shared services were not touched.
- Real-send test (test mode off, a ZZ AUDIT postal address) went only to the mail catcher; settings were put back and re-checked field by field.
- Cleanup: all ZZ AUDIT creators, emails, the contact message and the suppression row are deleted. Leftovers are listed in section 4 (audit lines, 3 chat threads, 1 proposal, mails in the catcher).
- Other reports were read to avoid duplicates. Where an item is already there I give the ID instead of repeating it (DB-02, DB-04, DB-14, ARC-04, ARC-06, ARC-12, SEC-02, SEC-11).

## 2. Done well

- **One path to send.** `sendEmail` is called only from `POST /api/emails/[id]/send` (grep of the whole app). No cron, timer, scheduled function or Claude tool sends. Approving never sends: after approve, 0 new mails arrived in 2.5 s.
- **The send gate holds under pressure (tested).** Two simultaneous POSTs for one approved email: one 200, one 409 `not_approved`; a later replay: 409; one mail in the catcher. Two different approved emails fired at the same instant: one 200, one 429 `too_soon`. Sending a draft: 409. Editing an approved email puts it back to draft (409 on send).
- **Direct tampering is refused.** A worker's PATCH of an email to `sent`, `sending` or `replied` returns 400; a worker calling `reserve_send` directly returns 403 (service role only).
- **Daily limit** works (limit set to the number already sent: 429 `daily_limit`; raised by one: the next send passed). Test and real sends are counted separately, `sending` rows count, and the minimum gap looks at all kinds. Limit, gap, test mode and postal address are owner-only (`requireOwner`).
- **Test mode** works: every mail went to the test address with `[TEST]` in the subject, the creator was not touched. With no test address: refused with a clear message (409), the email stays `approved`, nothing sent. The settings form and the database both reject an empty address while test mode is on.
- **Real send** needs a postal address (database refuses without it); the address, sender line and unsubscribe link were all in the mail body; the creator moved to `contacted`.
- **Opt-out blocks every path I tried:** after the link opt-out, send (409), new draft (400 by `emails_guard`), approve of an old draft, and a worker who flipped the creator back to `new` (the address is on the suppression list: draft 400, send 409). Tampered token: 404. Opening the page does not unsubscribe (mail scanners are safe); only the button does.
- **Logging:** each email has `created`, `approved`, `sending`, `sent` (or `failed`) audit lines with the real actor (worker@ or owner@); the email row keeps `drafted_by`, `approved_by`, `sent_by`; `email.drafted` (with `via: claude` for Claude drafts), `email.unsubscribed` and `settings.updated` (with before and after values) are logged.
- **Keys stay on the server:** I searched all 31 files in `.next/static` and all 12 in `public/` for the fake Anthropic, SMTP, service-role, unsubscribe and YouTube values and for `sk-ant-` patterns: none. Every module that reads a secret has `import 'server-only'`. Error paths log only the error type; a fake `sk-ant-...` string inside a 500 body from the fake Claude never reached the log or the database.
- **Failures are clean.** SMTP down: 409 in 0.1 s, email `failed` with a short error, nothing stuck, retry goes back to draft. Claude down, 500, refusal, bad JSON, empty fields on Compose: nothing half saved, "0 drafts saved. Not drafted: name". Assistant with Claude down or 500: "Claude could not be reached", the lock is released, the user message is stored. A 21 s slow answer on Compose still finished.
- **Prompt hygiene:** Claude never receives email, phone or notes (checked in the real request in the fake log); database text reaches the assistant as `<untrusted>` with all angle-bracket look-alikes removed; the assistant has no send, delete or export tool, drafts only land as `draft`, all other changes are proposals, a do-not-contact creator cannot be moved by the tool or at approval, 10 drafts per message, 12 steps, 100 messages a day, owner only (worker: 403 and redirect).

## 4. Not checked or limits

- **Not run:** a real Anthropic call (forbidden), a real SMTP server, Gmail limits and bounce handling (the app has no bounce or complaint intake), delivery or spam-folder behaviour, and the Netlify 10 to 60 s function limit. SMTP timeouts: `nodemailer` is created with its default timeouts (2 min connect, 10 min socket); a function stopped mid-send leaves the email `sending` forever, and an SMTP error after the server accepted the data can mark `failed` and allow a duplicate on retry. Stuck `sending`: already DB-04 and ARC-04. Compose time-outs: ARC-06. SMTP error text in the log: ARC-12.
- **Prompt injection is tested with a scripted fake, not a real model.** I showed what reaches the model (wrapped data, no personal fields) and what a model that obeyed would be able to do: save drafts (EML-02, EML-05), create pending proposals (EML-06) and read tool data. A refusal to move a do-not-contact creator held, and nothing could send, delete or export. How a real model behaves was not measured.
- **Assistant timeouts on Netlify:** the 270 s default deadline is only safe if `ASSISTANT_DEADLINE_MS=50000` is set in Netlify (documented in the README); not checkable here. A 21 s Compose answer worked; a 40 s assistant answer was not run to the end.
- **Legal notes in short (observations, not legal advice):** see EML-11. Items for a lawyer: whether inferred consent applies to creators' public channel addresses (Spam Act), the right lawful basis and the notice wording (GDPR), and whether Smallfold's lack of a registered entity and postal address (production state) allows real sending at all.
- **Leftovers I could not delete:** the audit log is append-only, so ZZ AUDIT audit lines stay. Three Claude chat threads titled `hello there`, `CRAFT_500 hello` and `Please summarise my inbox` and one proposal (summary "Add creator ZZ AUDIT Attacker") remain on the local database, because nobody can delete them (EML-10; the titles come from my first messages, so they do not start with ZZ AUDIT). The mail catcher still holds my ZZ AUDIT mails; I did not clear it because that would delete other agents' mails.
- **Settings:** `daily_send_limit`, `test_mode`, `test_email`, `sender_postal_address`, and the rest of the row were restored and compared with the saved copy.

Score: 7/10 — the send gate, limits, test mode, opt-out blocking, logging and secret handling are solid and survived concurrent and tampered requests, but the one-click unsubscribe header is broken and the draft validator and opt-out handling leave the legal and "no invented facts" rules to people.
